# 이 정도 코드를 짤 수 있는 연차 감각

냉정한 기준이다. 회사/팀에 따라 다르지만 면접용 감각은 아래와 같다.

| 수준 | 가능 범위 |
|---|---|
| 학부 1~2학년 | 단일 언어 토이 프로젝트, REST API 호출, 간단 대시보드 |
| 학부 3~4학년 상위권 | C++/Java/Python을 분리한 시스템 구조 이해, Docker 실행, 기본 테스트 |
| 신입~1년차 | 요구사항 문서, API, DB, 기본 로깅, 예외 처리, 단위 테스트 작성 |
| 1~3년차 | timeout/retry, 장애 대응, 운영 로그, 자동화 테스트, 간단한 설계 문서화 |
| 3~5년차 | 장애 복구 설계, observability, 보안, 성능 테스트, 코드 리뷰 기준 정립 |
| 5년차 이상 | 안전/품질 프로세스, 요구사항 추적성, 인증 대응, 시스템 전체 trade-off 판단 |

이 프로젝트의 현재 코드는 `신입~2년차가 멘토링을 받으며 만들 수 있는 구조`에 가깝다.
혼자 처음부터 완전히 설계하고 안정화까지 한다면 보통 `2~3년차 이상` 감각이 필요하다.

단, 포트폴리오 관점에서는 모든 코드를 암기할 필요가 없다. 중요한 것은 다음 세 가지를 설명하는 것이다.

1. 왜 C++/Java/Python/C# 역할을 나눴는가
2. 왜 timeout/retry/queue/logging을 넣었는가
3. 요구사항이 어느 코드와 테스트로 연결되는가
